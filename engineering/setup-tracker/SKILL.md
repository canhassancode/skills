# Setup tracker

Configure how the issue skills (`triage`, `to-prd`, `to-issues`, `pickup`, `morning-brief`) talk to *this* repo's tracker. This is the per-repo tracker config the skills resolve at run time.

## Process

1. **Ask which tracker** this repo uses: `github` (the default) or `linear`.

2. **Write the preference** where the skills resolve it — a `tracker:` line under an `## Issue tracker` section in the repo's `CLAUDE.md` (create the section if absent):

   ```md
   ## Issue tracker

   tracker: linear
   ```

3. **GitHub** — nothing else needed. The skills load `~/.claude/skills/triage/issue-tracker-github.md` and bootstrap the canonical labels on first use.

4. **Linear** — the workspace is usually shared, so follow **adopt-don't-impose**: never bootstrap. Inspect the live workspace and scaffold the mapping:
   - `list_teams`, `list_issue_statuses`, `list_issue_labels` to read the current taxonomy.
   - Map each canonical role (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`, `bug`, `enhancement`, `prd`) onto an **existing** label, workflow state, or Project mechanism. Where no target exists, ask the maintainer — do not create taxonomy.
   - Record the mapping in the repo's `CLAUDE.md` (or a repo `docs/agents/triage-labels.md`) so the Linear adapter uses it.
   - Flag any duplicates you find (a ported label sitting beside a native one) for the maintainer to retire.

5. **Set the `triage-disclaimer` preference** — ask the maintainer whether AI-generated triage comments should carry the disclaimer (`> *This was generated by AI during triage.*`). The default is **on for Linear** (shared team space) and **off for GitHub** (personal tracker). If the maintainer wants the non-default, write under the `## Issue tracker` section:

   ```md
   triage-disclaimer: off
   ```

   When unset, the skills resolve the tracker-appropriate default.

6. **Confirm** the written config back to the maintainer.

The Linear operation conventions live in `~/.claude/skills/triage/issue-tracker-linear.md`.
